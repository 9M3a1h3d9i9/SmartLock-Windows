# V0.3 — Security Engine

## Goal

Turn the V0.2 event logger into a typed, deterministic security domain that can classify security events and derive incidents without collecting Windows credentials.

## Delivered

- Strongly typed security event categories.
- Explicit severity levels: Info, Warning, High, Critical.
- Explicit event lifecycle states: Observed, Accepted, Rejected, Resolved.
- Thread-safe in-memory event storage with snapshot reads.
- Stable incident identifiers derived from recorded events.
- Deterministic policy evaluation for rejected authentication attempts and policy violations.
- Core and UI tests migrated to the typed event model.

## Security boundary

V0.3 does **not** replace the Windows lock screen, intercept Winlogon, collect Windows passwords/PINs, store biometric templates, or capture the camera covertly.

The policy engine operates only on application-level security events.

## Quality gate

- Full solution restore/build/test must pass on Windows CI.
- Security-event tests must cover typed fields, snapshots, validation, and policy outcomes.
- No credential or secret persistence may be introduced.

## Next

V0.4 will build a smart context/policy layer on top of the security engine, with explicit separation between detection, policy decisions, and presentation.
