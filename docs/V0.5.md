# V0.5 — Windows Integration

## Goal
Connect SmartLock to a real, read-only Windows session signal without replacing the Windows lock screen or intercepting authentication.

## Delivered

- Added `SmartLock.Infrastructure` for Windows-specific adapters.
- Added `ISessionSignalProvider` to keep Core independent of Win32 APIs.
- Added `WindowsSessionSignalProvider` using the documented `GetLastInputInfo` Win32 API to estimate current user idle duration.
- Added a one-second `SessionContextMonitor` in the desktop app.
- The UI now displays live session state and idle duration.
- OS-signal failures are isolated so a missing signal does not terminate the UI loop.

## Security Boundary

V0.5 is intentionally read-only with respect to Windows session state. It does not:

- replace or hook Winlogon;
- intercept Windows passwords, PINs, or biometric credentials;
- store Windows credentials or biometric templates;
- capture webcam data;
- silently transmit telemetry.

## Local Verification Required

Because this milestone calls a Windows API and runs a WPF desktop process, local execution on Windows is required for behavioral verification. GitHub CI can verify compilation and unit tests, but it cannot replace testing the live idle signal on the target machine.

## Quality Gate

- Solution builds on Windows with .NET 10 SDK.
- Existing Core/UI tests remain green.
- Application starts and continuously updates the session indicator.
- Ctrl+E still exits the development shell.
- No credential value enters the application state model.

## Next

V0.6 should add a proper Windows session notification adapter and configurable policy thresholds, while preserving the same security boundaries.
