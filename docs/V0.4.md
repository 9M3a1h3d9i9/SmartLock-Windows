# V0.4 — Smart Context Awareness

## Goal

V0.4 introduces a deterministic session-context layer so SmartLock can reason about the current workstation state without collecting credentials or performing authentication itself.

## Delivered

- Added `SessionState` with `Active`, `Idle`, `Locked`, and `Restricted` states.
- Added immutable `SessionContext` containing observation time and idle duration.
- Added `SessionContextEvaluator` with deterministic state evaluation.
- Added unit tests for active, idle, locked, and invalid-duration cases.
- Removed credential input from the UI ViewModel so authentication secrets do not become application state.

## Security boundary

The context layer is observational. It does not intercept Winlogon, replace Windows authentication, store Windows credentials, or capture biometric data. Future OS integrations must remain behind explicit infrastructure/security interfaces and use documented Windows APIs.

## Quality gate

- Domain logic remains UI-independent.
- Context decisions are deterministic and testable.
- Negative idle durations are rejected.
- Authentication input is not copied into the ViewModel.

## Next

V0.5 will focus on controlled Windows integration: idle/session signals, application lifecycle integration, and safe platform adapters while preserving the security boundary.
